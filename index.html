Phase 1: Problem Analysis and Requirements

1. Problem Statement: Air pollution is a major environmental and public health crisis. Particulate matter ($PM_{2.5}, PM_{10}$) and toxic gases ($CO, NO_2, SO_2, O_3$) cause severe respiratory and cardiovascular damage. Monitoring informs current status, while predictive forecasting allows schools, hospitals, and citizens to take proactive protective actions.


2. Project Objective: Build a data science driven web system ("AirSense") to monitor real-time pollutants, compute standard AQI, and predict 24-hour ahead AQI values using machine learning.


3. Target Users: General public, students, schools and colleges, environmental researchers, and municipal authorities.


4. Proposed Architecture: 3-layer pipeline comprising Data Collection (CPCB historical archives + OpenWeatherMap REST API), Data Science & ML Engine (Cleaning, AQI sub-index calculation, Random Forest regression), and Web Presentation Layer.


5. Scope: Version 1 covers major urban centers, historical supervised ML modeling, and a responsive web dashboard with health advisories. Physical IoT sensor kits and satellite GIS processing are reserved for future phases.

Phase 2: Data Collection Specification

1. Data Attributes: $PM_{2.5}, PM_{10}, CO, NO_2, SO_2, O_3$, Temperature, Humidity, Date, Time, Location, and Target AQI.


2. Sources: Historical records from CPCB India (2015-2020), live pollutant REST APIs from OpenWeatherMap, and meteorological data from Open-Meteo.


3. Recommended Primary Dataset: Air Quality Data in India (2015-2020) containing ~29,500 daily records across 26 cities, 16 features, and official standard AQI targets.


4. Storage Strategy: CSV files for raw datasets (`data/raw/`) and embedded SQLite for caching live API logs.


5. Baseline Quality Inspection: Auditing missing percentages (e.g. $PM_{10}$ ~37%, $PM_{2.5}$ ~15%), 0 duplicate records, scale validation ($CO$ in $mg/m^3$, others in $\mu g/m^3$).

Phase 3: Data Preprocessing Specification

1. Loading & Schema: Loaded 93 daily multi-city records with 12 features across criteria pollutants and weather indicators.


2. Missing Value Imputation: Applied city-wise forward-fill (`ffill`), backward-fill (`bfill`), and median imputation to preserve temporal continuity.


3. Physical Boundaries & Outliers: Clipped negative pollutant concentrations to 0.0, constrained humidity to [0, 100%], and applied 99th percentile soft-capping to prevent sensor glitches while retaining genuine winter smog spikes.


4. Feature Engineering: Derived `Year`, `Month`, `Day`, `DayOfWeek`, `Is_Weekend`, `Season` (Winter/Summer/Monsoon/Post-Monsoon), and `PM_Ratio` ($PM_{2.5} / PM_{10}$ combustion index).


5. Categorical Encoding & Scaling: One-Hot Encoded `City` and `Season` features. Continuous variables scaled via `StandardScaler` ($\mu=0, \sigma=1$).


6. Exported Assets: Clean dataset exported to data/processed/city_day_cleaned.csv, features_X.csv, and target_y.csv.

Phase 5: Machine Learning Model Development & Evaluation

1. Models Trained & Evaluated: Linear Regression, Decision Tree, Random Forest, and Gradient Boosting Regressor.
